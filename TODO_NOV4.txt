PART A: CONNECT TO A REAL SWITCH ROOM
-------------------------------------

A0. Prerequisites (~10 min)
  [ ] Claude Code installed and logged in:   claude --version
  [ ] A private Discord server with a channel #teampilot
      (or install Docker Desktop and use Switch's bundled Mattermost instead).
  [ ] Push this repo to GitHub (public).
  [ ] Create a public repo "teampilot-demo-app" containing ONLY the two
      files from demo-repo/ (validator.py, test_validator.py). The agents
      clone and fix that repo during the demo.
  [ ] Build the paste-ready instructions with your demo repo URL:
        python3 scripts/build_agent_prompts.py https://github.com/<you>/teampilot-demo-app
      CHECK: agents/dist/ contains 4 teampilot-*.txt and room-instructions.txt

A1. Switch Console and server (~10 min)
  [ ] Download Switch Console for macOS: https://github.com/sandbox-quantum/switch/releases
  [ ] Add a server -> "Run a server on this computer".
  [ ] Home -> Messaging apps -> connect Discord
      (docs.switchagents.ai/switch-rooms/deploy/messaging-apps/discord),
      or accept the bundled Mattermost.
  [ ] Home -> Messaging apps -> Link YOUR account. Without this, your own
      agents refuse you.
  CHECK: the sidebar says "Running locally"; your account shows as linked.

A2. Register the 4 specialists (~15 min). Repeat for role in
    frontend, backend, testing, reviewer:
  [ ] Your Agents -> + :
        Name ............ teampilot-<role>   (exactly; the backend expects these)
        Description ..... one line
        Instructions .... paste agents/dist/teampilot-<role>.txt
        Run location .... This computer
        Directory ....... an EMPTY folder, e.g. ~/agents/teampilot-<role>
        Provider ........ Claude Code
        Who can talk .... Anyone
        Auto mode ON, Bypass permissions OFF
  CHECK: 4 cards reading "Claude Code · this computer".

A3. Register the coordinator identity (~5 min)
  [ ] Your Agents -> + :
        Name teampilot-coordinator, Provider Claude Code (unused),
        Directory = <this repo>/backend, Who can talk = Anyone,
        Instructions = the quoted block in agents/coordinator.md
  [ ] Never start a session for it. The TeamPilot backend is its client.
  [ ] Run:  python3 scripts/switch_env.py
      CHECK: it prints "updated backend/.env: SWITCH_API_ENDPOINT=..., SWITCH_API_TOKEN=***"
      If it says "not found", Console put the file elsewhere: find it with
        find ~ -path '*/.switch/agents/teampilot-coordinator.json' 2>/dev/null
      then re-run with --json <that path>.

A4. Create the room (~10 min)
  [ ] Your Rooms -> Create room: messaging app Discord, name "teampilot",
      add all five teampilot-* agents, Instructions = paste
      agents/dist/room-instructions.txt
  [ ] In Discord, post "hello" in the channel. On Discord, the first post is
      what creates the room.
  [ ] In the channel:  !list-agents        -> all five listed
  [ ] Get the room id from the room's page in Switch Console, then:
        python3 scripts/switch_env.py --room <ROOM_ID>
  CHECK: !agents-status lists the specialists (⚪ is normal before first use).

A5. Start TeamPilot against the room (~5 min)
  [ ] cd backend && .venv/bin/python -m uvicorn app.main:app --port 8000
      The log must say: "Switch adapter starting (agent ..., room ...)"
  [ ] curl localhost:8000/health   -> "switch":"connected"
      If it says "error", run: curl localhost:8000/api/switch/status
      and read last_error:
        - 401        -> wrong token; re-run scripts/switch_env.py
        - 403 / 409  -> wrong room id, or the coordinator is not in the room
        - connection refused -> SWITCH_API_ENDPOINT must be the agent-bridge
          API URL (GET <endpoint>/health returns 200), not the Gateway URL
  [ ] cd frontend && npm run dev   -> the sidebar pill says "Switch: connected"

A6. First real round trip (~15 min). This is the moment Switch is proven.
  [ ] From your phone, in #teampilot:
        @teampilot-coordinator Investigate the login validation bug, fix it, and verify the solution.
  [ ] Expect within seconds: the task graph on /tasks, the plan plus a
      TASK_ASSIGNED card in Discord addressed to teampilot-backend, and a
      "switch" badge (not "local") on /chat.
  [ ] Switch Console starts a Claude Code session for teampilot-backend, and
      it replies with a TASK_STARTED card.
  [ ] Approval prompts from Claude Code appear in the room. Answer them there.
  [ ] Try:  @teampilot-coordinator status
  If an agent answers in prose without a card, the coordinator replies with
  "⚠️ Your last message was not applied: ..." and the agent usually resends.
  If it keeps doing it, add to its instructions: "End EVERY message with
  exactly one ```json card."
  If nothing answers: run !agents-status. ⚪ means Console isn't running, or
  the agent's directory or provider is wrong.

A7. Rehearse (~30 min)
  [ ] Run the scenario end to end 2-3 times. For rehearsals, set
      STALE_TASK_MINUTES=5 in backend/.env.
  [ ] Optional: ANTHROPIC_API_KEY in backend/.env makes Claude plan the tasks
      instead of the rule planner.
  [ ] Optional: the same TEAMPILOT_API_TOKEN in backend/.env and
      frontend/.env.local locks the API.
